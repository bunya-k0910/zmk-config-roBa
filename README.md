## 現在の試用: Mac Mouse Fixによるジェスチャー（2026-09-13）

目的は、Pを押してボールを動かす量に合わせて画面を動かし、ちらっと確認して戻れる操作にすること。
2026-09-13、ユーザーは前の方式について「初回はスムーズだが、次の入力までの猶予が長すぎる」「シュッシュッと移動したい」と評価し、Mac側でジェスチャーに変換する試用に同意した。

- P・スラッシュは、押している間マウスの中央ボタンを送る。短押しの文字入力は維持する。
- ボールの移動量は通常のポインター入力としてMacへ送り、Mac Mouse Fix 3.0.8で中央ボタンのドラッグを「Spaces & Mission Control」に割り当てる。
- 中央ボタンのクリック・長押し・ダブルクリックには操作を割り当てない。Mac Mouse Fixが有効な間はジェスチャー用の押下だけを扱う。
- Mac Mouse Fixの `General.scrollKillSwitch = true` とし、既存のスクロール補正はMosに任せる。
- I長押しのスクロール、ロータリー、既存のブラウザ移動キーは変更しない。

この方式はMac Mouse Fixが有効であることを前提とする。無効時は中央ボタン入力が通常のクリックとしてMacへ届く。
ファームウェア内の旧ジェスチャー判定は接続・コンパイルしない。旧実装とテストは過去の試用記録・切り戻し用に残す。
実機での追随性、P短押し、Mosとの共存は書き込み後に確認する。

## 旧方式: ファームウェア内での画面切り替え判定（2026-09-13 試用終了）

- 上下: Mission Control / アプリのウィンドウ一覧を1回実行し、操作用レイヤーを解除するまで再発火しない。
- 左右: ひと転がしでデスクトップを1つ移動する。350 ms以上動きが止まると次の操作を受け付ける。
- 縦横を同じセンサー報告内で比較し、大きい方向を採用する。同量なら方向が定まるまで待つ。実行後の同じ転がしでは別方向へ切り替えない。

判定量は従来と同じ240、キーの押下時間は30 ms。調整値と割り当ては `config/roBa.keymap` の `roba_gesture` にある。
通常のポインター移動、I長押しのスクロール、ロータリーは従来の処理を使う。

独自処理は右側の入力処理として組み込む。センサードライバーの距離ごとの繰り返し入力は使用しない。
繰り返し入力をためるキューは使わず、現在のレイヤー有効期間の実行待ちは最大1件に限定する。
素早く離して押し直した操作は、前のキーを離してから実行する。
操作用レイヤー解除時は未実行の入力を破棄し、押下済みのキーは必ず離す。
ZMK v0.3のレイヤー別入力処理では停止の戻り値が伝わらないため、消費したXY値も0にしてポインターへの漏出を防ぐ。

判定処理のローカル検証:

```sh
cc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined tests/gesture_test.c -o /tmp/gesture-test
/tmp/gesture-test
```

この検証とファームウェアのビルドはGitHub Actionsでも実行する。実機での停止間隔・操作感は別途確認する。
