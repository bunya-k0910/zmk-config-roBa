## 現在の試用: 一振りをネイティブショートカットへ変換（2026-09-13）

ユーザーは「Pを保持したまま右・右・左などを素早く入力し、各入力で1画面を最後まで切り替えたい」と指定した。距離ごとのドラッグ確定方式は「半分で止まる、2画面進む、Pの解放を待つ、速すぎる」と評価され、置き換える。ユーザーがAutoRaise 5.3.0のMouse WarpをオフにするとControl＋矢印の連続切替が改善した。AutoRaiseだけが全症状の原因と確定したわけではない。

- P・スラッシュの保持中、右/左の一振りでControl＋左/右を送る。ユーザーの追加指定に合わせて左右を反転した。上/下はControl＋上/下でMission Control/アプリのウィンドウ一覧を呼ぶ。
- 初期判定量は直進64センサー単位。別軸の動きは半分を差し引き、小さな斜めのずれが長い横移動中に縦操作へ育たないようにする。同じ方向には距離で再発火せず、80 msの非ゼロ入力の途切れ、または十分な別方向の移動で次の操作を認識する。80 ms未満でつながる同方向の二振りは区別できず、実機で残る確認点とする。
- Pを離すまで切替を待たない。認識済みのキー操作は30 msで解放し、次のキー押下とは10 ms離す。画面アニメーションの待ち時間は追加しない。キー押下中に認識した方向は最大4件を順に保持し、古い方向を新しい方向で上書きしない。異常な入力集中で満杯になれば追加を拒否してログに残す。
- キー解放時には途中の判定を消す。既に認識した操作とそのキー解放は完了させる。キーを離したこと自体では新しい操作を発生させない。P・スラッシュの標準hold-tap、文字順序、ジェスチャー使用後の文字抑止は維持する。
- 中央ボタンと8倍のマウス移動は送らない。Mac Mouse Fixによるジェスチャー変換は不要となる。通常ポインター、I長押しスクロール、ロータリーは変更しない。

9月13日のローカル計測はroBaのX/Yと時刻だけを記録した。ユーザーは最初Pなし、途中からPありと説明した。加工済みの区間を生のセンサー量として扱わず、方向の意図ラベルも推定で固定しない。ホストでの受信間隔に約133 msの短い停止があることを80 ms初期値の参考にした。Bluetoothのまとめて届く影響もあるため、その値があらゆる一振りを正しく分ける証明ではない。元のCSVはローカルに置き、リポジトリへ追加しない。

ローカルの判定/順序テストとGitHub Actionsのサニタイザー付きテスト・左右ビルドを実施する。実機での連続入力、上下、P/スラッシュ文字、スクロールの体感は別途ユーザーが確認する。Macが遷移中に全入力を受理する保証や、トラックパッドと同一の操作感を静的テストから主張しない。

9月13日、ユーザーはeb81da3を書き込んだ左右切替を「完璧」と評価した。追加指定は左右方向の反転と上下不動の修正。判定量・停止間隔・キー送信時間は変更しない。上下の不動は実装時に修飾キーフラグ2359296（0x240000 = Control + NumericPad）を誤ってControl + Optionと解釈したことによる割り当てミスと判明。macOS SDKのNSEvent.hと現在のショートカット設定を照合し、余分なOptionを除いた。前版の「設定に一致する」という説明は誤りだった。

ユーザーは、希望の動作達成後の不要アプリ削除と、実測用システムの整理を依頼した。Mac Mouse Fix 3は30日試用後2.99米ドル+税の買い切り（https://macmousefix.com/ 、2026-09-13確認）。無料を前提とする追加希望に合わせてMos 4.0.2へ戻す方針へ変更。現状のZMKショートカット方式はMac Mouse Fixに依存しない。AutoRaiseの改善した設定は維持する。計測アプリの追加権限・一時ファイルも整理する。実施状態はfirmwareの検証記録に残す。

```sh
cc -std=c11 -Wall -Wextra -Werror tests/gesture_stroke_test.c -o /tmp/roba-gesture-stroke-test
/tmp/roba-gesture-stroke-test
```

## 旧試用: Pを保持したまま距離ごとにドラッグを確定（2026-09-13、置き換え）

2026-09-13、ユーザーはMac Mouse Fixで「トラックボールに吸いついている」ことを確認した。一方「画面の10パーセントくらいしか動かない」「Pを離すとようやく動き出す」と報告し、少ない動きで追随し一定量で確定、Pを保持したまま次の方向へ続ける変更を承認した。確定後の逆方向操作は、元の画面へ戻る新しい操作として扱う。

- 2026-09-13の追加指定により、ジェスチャーの左右方向を前の試用から反転した。上下方向は維持する。
- P・スラッシュの押下中は操作用レイヤーを即時有効化する。中央ボタンを押し続ける処理はキーから外し、個々のジェスチャーだけが所有する。
- ボールの移動量をこの操作中だけ8倍にする。横160・縦96のセンサー移動量で中央ボタンの解放を送り、次のセンサー報告から新しい操作を受け付ける。停止待ち時間や繰り返しの予約はない。大きな一報告の余剰移動は蓄積せず捨てる。
- Mac Mouse Fix 3.0.8が最初の7画素超の入力を軸決定だけに使う実装に合わせ、軸決定用の16画素を移動本体と別の報告で送る。押下・移動・解放を順に送る。
- 確定前に引き返すと画面も戻り、原点まで戻ったところで現在の操作を終了する。縦横の軸は1回の操作内では固定する。確定後は別の軸も選べる。
- 標準hold-tap（200ms・tap-preferred）の文字順序制御を維持し、タップ時にジェスチャーを始めていなければP・スラッシュの文字を送る。短時間でもジェスチャーを使った場合は文字を送らない。
- 通常のポインター移動、I長押しスクロール、ロータリーのファームウェア処理は変更していない。

Mac側はMac Mouse Fix 3.0.8の中央ボタン1段階の「Click and Drag → Spaces & Mission Control」のみを割り当てる。クリック・長押し・ダブルクリックの追加割り当てはしない。
ユーザーの承認により、Mos 4.0.2を一時停止しMac Mouse Fixのスクロールも有効化した。滑らかさはregular、速度medium、反転は既存のtrueで試す。Mosは削除せず、二重稼働を避けるためログイン時起動もオフにした。元のスクロール設定は保持しており、Mosの再起動とMac Mouse Fixのスクロール停止で戻せる。

静的検証は `tests/gesture_drag_test.c` とファームウェアビルド。`tests/gesture_test.c` は旧方式の履歴用テスト。新方式の実機での確定距離、OSアニメーション中の連続・逆方向操作、短押し、スクロールの感触は書き込み後の確認対象。画面の大きさやmacOSの加速に左右されるため、この距離で必ず1画面になるとは未検証の段階では断定しない。

```sh
cc -std=c11 -Wall -Wextra -Werror tests/gesture_drag_test.c -o /tmp/roba-gesture-drag-test
/tmp/roba-gesture-drag-test
```

## 旧試用: Pの解放で確定するMac Mouse Fixジェスチャー（2026-09-13）

目的は、Pを押してボールを動かす量に合わせて画面を動かし、ちらっと確認して戻れる操作にすること。
2026-09-13、ユーザーは前の方式について「初回はスムーズだが、次の入力までの猶予が長すぎる」「シュッシュッと移動したい」と評価し、Mac側でジェスチャーに変換する試用に同意した。

- P・スラッシュは、押している間マウスの中央ボタンを送る。短押しの文字入力は維持する。
- ボールの移動量は通常のポインター入力としてMacへ送り、Mac Mouse Fix 3.0.8で中央ボタンのドラッグを「Spaces & Mission Control」に割り当てる。
- 中央ボタンのクリック・長押し・ダブルクリックには操作を割り当てない。Mac Mouse Fixが有効な間はジェスチャー用の押下だけを扱う。
- Mac Mouse Fixの `General.scrollKillSwitch = true` とし、既存のスクロール補正はMosに任せる。
- I長押しのスクロール、ロータリー、既存のブラウザ移動キーは変更しない。

この方式はMac Mouse Fixが有効であることを前提とする。無効時は中央ボタン入力が通常のクリックとしてMacへ届く。
ファームウェア内の旧ジェスチャー判定は接続・コンパイルしない。旧実装とテストは過去の試用記録・切り戻し用に残す。
実機での追随性、P短押し、Mosとの共存は書き込み後に確認する。

## 旧方式: ファームウェア内での画面切り替え判定（2026-09-13 試用終了）

- 上下: Mission Control / アプリのウィンドウ一覧を1回実行し、操作用レイヤーを解除するまで再発火しない。
- 左右: ひと転がしでデスクトップを1つ移動する。350 ms以上動きが止まると次の操作を受け付ける。
- 縦横を同じセンサー報告内で比較し、大きい方向を採用する。同量なら方向が定まるまで待つ。実行後の同じ転がしでは別方向へ切り替えない。

判定量は従来と同じ240、キーの押下時間は30 ms。調整値と割り当ては `config/roBa.keymap` の `roba_gesture` にある。
通常のポインター移動、I長押しのスクロール、ロータリーは従来の処理を使う。

独自処理は右側の入力処理として組み込む。センサードライバーの距離ごとの繰り返し入力は使用しない。
繰り返し入力をためるキューは使わず、現在のレイヤー有効期間の実行待ちは最大1件に限定する。
素早く離して押し直した操作は、前のキーを離してから実行する。
操作用レイヤー解除時は未実行の入力を破棄し、押下済みのキーは必ず離す。
ZMK v0.3のレイヤー別入力処理では停止の戻り値が伝わらないため、消費したXY値も0にしてポインターへの漏出を防ぐ。

判定処理のローカル検証:

```sh
cc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined tests/gesture_test.c -o /tmp/gesture-test
/tmp/gesture-test
```

この検証とファームウェアのビルドはGitHub Actionsでも実行する。実機での停止間隔・操作感は別途確認する。
